# Source-bound viewpoint links

The viewer's **Copy viewpoint link** control captures the live camera, hidden categories, section cut, selected element and technical/X-ray display mode. A recipient opens the same RVT file locally and chooses **Restore viewpoint**, or opens the link before loading that file. **Include current review markup** is an explicit opt-in checkbox, unchecked by default. Without that choice, review markup and its text stay outside the link.

The URL contains no model bytes, source filename, asset URL, credentials or private page query parameters. Opted-in markup includes its annotation text and source-space anchors in the URL fragment. The fragment is an encoded local state document; it does not fetch a model or any pasted URL. Unknown JSON fields are discarded. Comments, attached assets and other review exchanges remain outside the link.

Version 3 extends version 2 with a selected-element ID, display mode and optional bounded review markup. Selection must be a positive safe integer present in the open source model's element bounds or mesh owners. A foreign ID is refused during capture and import; `null` explicitly clears selection. The only portable display modes are `technical` and `xray`. Omitting these controls leaves the existing selection/display mode unchanged when restoring older links.

Version 2 extends the camera-only version 1 contract with category visibility and Reviter's existing section controls: enabled state, X/Y/Z plane or box mode, model-bounds offset between zero and one, and reverse side. Version 1 links still restore their camera without applying viewer controls. Version 2 rejects version 3-only fields rather than interpreting them through an older contract. Unsupported versions and malformed controls are rejected.

All versions require an exact SHA-256 match of the source RVT bytes. Version 2 and version 3 also verify the existing review fingerprint before restoring model-bounds display controls, selection or markup. A link opened without a model remains pending until the matching RVT is loaded. Camera coordinates remain canonical Revit model feet and use the existing source-origin conversion; a registered camera's pose is restored in the open recovered model frame.

Version 2 and version 3 state capture require the recovered RVT view so section fractions use native model bounds. Camera-only version 1 still supports existing registered reference camera frames. Copying from floor review or an isolated level asks the user to close that display first, because these links do not encode floor-specific state. Restoring viewer state exits floor display and level isolation, switches to the recovered RVT model, and applies its controls and camera. Source-bound links do not modify geometry or navigation.

## Optional review markup

Included pencil, arrow, cloud and text strokes retain their canonical source anchors, tool, color, world-space width and optional text. Capture accepts recovered RVT and registered reference IFC strokes; standalone unregistered reference-model strokes and unknown source frames are refused. Existing `pointsFeet` anchors are retained. Recovered scene points use the source origin, while registered reference points and widths convert from metres to feet. Imported source anchors are reanchored into the recovered model's current local scene frame.

A fragment can carry at most 16 strokes, 128 points in total, 128 points per stroke and 256 text characters per stroke. Stroke IDs use at most 96 ASCII letters/digits, colons, underscores or hyphens and must be unique in an imported batch. Colors are six-digit hex values. Widths must be finite, greater than zero and at most 1,000 feet; coordinates must be finite triples within the supported 100-million-foot world range. Invalid tools, control characters, malformed points, duplicate IDs and aggregate budget overruns are rejected. Newlines and tabs in annotation text are preserved. These shape limits apply to direct capture/merge helpers as well as decoded links.

Import merges markup into the current local strokes. Equal recovered-source content is deduplicated even when its incoming ID differs. An ID collision with different content receives a fresh `shared:…` ID; existing local strokes remain intact. Imported strokes receive the local import timestamp and are persisted through the existing markup store. Local undo/redo stacks reset when the merged markup is applied. A link without opted-in annotations does not replace local markup.

The category list is deduplicated and sorted, with at most 64 names of 96 characters each. Control characters, invalid numeric values and malformed sections are rejected. The entire fragment remains limited to 4,096 characters, so long category lists or valid but large markup can still exceed the URL budget. The existing markup sidecar remains available for larger or unregistered review content.

## Source and validation

The source design is `rvt-rs/src/ifc/share.rs` at commit `1c3d337dbd2a6810e9dfad68fe99857843d67387` (Apache-2.0, existing attribution in `docs/rvt-semantic-attribution.md`). Its optional source identity and section-box representation are adapted to Reviter's required source hash and existing section controls.

All **20 focused tests** in `tests/viewpoint-links.test.ts` passed. Coverage includes legacy version 1/version 2 contracts, selected bounds/mesh owner scope and foreign-ID refusal, explicit selection clearing and display modes, source/layout mismatch refusal, optional UTF-8 markup, canonical anchors and metre width conversion, reanchoring, aggregate limits, malformed controls and markup, unknown-field projection, preserved local strokes, content deduplication, collision renaming and direct helper hardening. Scoped ESLint and whitespace checks passed.

The existing [version 2 production browser validation](generated/rvt-viewpoint-state-browser-validation.json) passed all nine desktop/mobile checks with zero browser errors and zero horizontal mobile overflow. Changing category visibility and section clipping changed the rendered canvas pixels; restoration reproduced the original canvas PNG SHA-256 exactly. The [version 3 production browser validation](generated/rvt-viewpoint-v3-browser-validation.json) passes all 12 desktop/mobile checks with zero browser errors and zero mobile overflow. It verifies actual selection/display-mode capture and restore, optional markup capture, repeated-import deduplication, unchecked markup privacy, matching-file reload and identical restored canvas pixels. The earlier version 2 report remains a separate historical result.
